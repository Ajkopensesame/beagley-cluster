# CAN Health Baseline and Diagnostic Report v1

The CAN reverse workbench can compare an owner-authorized suspect vehicle
against a known-good decoded baseline for the same vehicle platform. This is a
diagnostic evidence workflow. It is not a repair directive, safety
certification, warranty decision, or substitute for mechanic validation.

## Baseline Document

Create a pseudonymous consent record before using customer data:

```bash
python3 -m tools.can_reverse_workbench consent \
  --out /path/to/car_b_consent.json \
  --owner-reference "work-order-1234" \
  --vehicle-profile "make model year engine trim ecu-calibration" \
  --purpose "owner-authorized engine fault triage" \
  --retention-days 30 \
  --owner-consent
```

Generated by:

```bash
python3 -m tools.can_reverse_workbench baseline \
  --decoded-good /path/to/car_a_vehicle_state_overlay.jsonl \
  --out /path/to/car_a_health_baseline.json \
  --vehicle-profile "make model year engine trim ecu-calibration" \
  --purpose "known-good baseline for owner-authorized diagnostics" \
  --retention-days 30 \
  --owner-consent
```

Top-level fields:

- `version`: currently `1`.
- `kind`: `can_health_baseline`.
- `generatedAt`: UTC timestamp.
- `source.decodedLog`: decoded JSONL source.
- `vehicleProfile`: exact platform label, including ECU calibration when known.
- `responsibleUse`: owner consent, purpose, read-only capture requirement,
  consent record summary when supplied, retention policy, privacy rules, and
  limitations.
- `stateRules`: coarse operating-state definitions used for bucketing.
- `states`: per-state signal statistics.

Each signal state contains:

- `count`
- `mean`
- `stdev`
- `min`
- `p05`
- `median`
- `p95`
- `max`

## Diagnostic Report

Generated by:

```bash
python3 -m tools.can_reverse_workbench diagnose \
  --baseline /path/to/car_a_health_baseline.json \
  --decoded-suspect /path/to/car_b_vehicle_state_overlay.jsonl \
  --out /path/to/car_b_diagnostic_report.json \
  --customer-report /path/to/car_b_customer_report.md \
  --vehicle-profile "make model year engine trim ecu-calibration" \
  --purpose "owner-authorized engine fault triage" \
  --consent-record /path/to/car_b_consent.json \
  --retention-days 30 \
  --owner-consent
```

Top-level fields:

- `version`: currently `1`.
- `kind`: `can_health_diagnostic_report`.
- `summary.status`: `anomalies_detected` or `no_strong_anomalies`.
- `summary.limitations`: report limitation text.
- `findings`: ranked anomaly evidence.

Each finding includes:

- `signal`
- `state`
- `severity`
- `confidence`
- `evidence.baseline`
- `evidence.suspect`
- `evidence.meanDelta`
- `evidence.zScore`
- `evidence.outsideBaselineEnvelopeRatio`
- `interpretation`
- `nextChecks`
- `notRepairDirective`: always `true`.

## Responsible Use

- Owner consent and a recorded diagnostic purpose are required.
- Consent records should use pseudonymous owner/work-order references rather
  than direct owner identifiers whenever possible.
- Capture must remain read-only.
- Generated baseline and diagnostic reports include a retention policy and
  delete-after date.
- VINs, location traces, timestamps, and driving behavior are sensitive owner
  data.
- Baselines should match exact make, model, year, engine, trim, ECU calibration,
  and guided test conditions.
- Findings must be validated with DTCs, freeze-frame data, service information,
  and physical tests before repair decisions.
